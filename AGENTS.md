
- Native (Capacitor) code lives in src/lib/native.ts and runs only behind isNative(); the web path must stay unchanged. Why: one codebase serves both the web app and the Android build.
- Release Android builds bundle dist; capacitor.config.ts sets server.url only when CAP_LIVE_RELOAD=1. Why: shipped APKs must not depend on the preview URL.
- Visual styling uses semantic Cosmic Obsidian tokens and shared UI primitives instead of page-level raw colors. Why: all web and Android screens must remain visually consistent and themeable.
- Push notifications are sent server-side: DB triggers call `dispatch_push_event` → `push-dispatch` edge function; never add client-side notify calls. Why: client paths were skipped and unreliable.
- Channels and payment requests live in the database; channel caches are viewer-scoped in memory and synchronization refreshes channels before posts. Why: reloads must fetch durable content without persisting private identity or mixing account state.
- Profile identity is authorized server-side by reciprocal direct messages, receiver-accepted calls, or subject-owned contacts; use `profileAccess` for client identity resolution and recipient-specific notification resolution. Why: empty chats, one-sided activity, public content and ID knowledge must not unlock personal identity.
- Managed avatar images use private authenticated storage downloads, never public or persistent signed URLs; identity caches must be viewer-scoped, revalidated, and held in memory rather than persisted with channel posts; invalidate mounted views and in-flight reads when access changes. Why: URLs and account-switch caches must not bypass profile authorization.
- Call setup and signaling reject stale async results by call/account generation; media controls invalidate superseded per-kind operations and serialize negotiated sender replacements; termination releases capture immediately. Why: delayed prompts, retries, and rapid hardware toggles must never resurrect a call, bypass mute, or disrupt redial.
- Wallet operations authorize and commit through transactional database RPCs, with ordered wallet locks, shared PIN failure counters, device checks and owner/payload-bound operation keys; edge handlers never write separate transfer legs. Why: a failed or repeated request must not lose money, double-pay, or bypass security.
- Wallet caches and mounted security gates are account-scoped and reject stale async results; balances change only through the server ledger. Why: account switching and local-only goals or schedules must not leak or fabricate financial data.
- Wallet-funded Stars and AI purchases use explicit PIN confirmation and authorized, idempotent purchase RPCs; legacy wallet-spend entrypoints must not be executable by clients. Why: opening a wallet or buying from another screen must not bypass per-payment PIN checks.
- Payment links use one same-origin generator and a server-resolved destination/request ID before PIN confirmation; resolving a destination does not authorize private identity. Why: QR/link payments must reach the correct recipient without weakening profile privacy.
- eTok and Story audiences are enforced on both rows and authenticated media downloads; content ownership, counters and poll choices are server-validated. Why: hidden metadata alone must not leave media or forged interactions accessible.
- Content routes remount on viewer/access changes; Live signaling requires active memberships and host heartbeats with serialized per-peer negotiation. Why: stale content, capture and signals must not leak across viewers or revive ended broadcasts.
